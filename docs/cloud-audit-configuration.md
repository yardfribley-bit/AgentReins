# 云审计服务器配置

配置文件：`Sources/AgentReins/Resources/audit-server.json`。

- 云服务器 IP：`165.154.254.180`。
- 服务器维护账号：`ubuntu`，仅用于服务器运维，不作为终端上传身份。
- SSH 密码不保存于代码、应用资源或本文档。
- 资源文件是禁用的默认声明，不包含设备令牌。真实注册读取 Application Support/AgentGuard/CloudAudit/device.json，权限 0600，包含 HTTPS endpoint、deviceID、token、enabledAt、uploadEnabled。
- 客户端按 10 秒周期检查持久化上传队列；首次事件有 8 秒合并窗口，不是逐事件立即发送。失败退避重试，凭持久化回执确认成功。
- 只上传启用之后开始、具有用户请求证据的新任务，不扫描历史任务回传；迟到 trace 允许两次后续补充。
- 每份新上传包附本机账号、设备名、内网 IPv4 与采样时间。可能有多个网络/VPN 地址；稳定 deviceID 才是设备关联键。本机账号不是已认证的企业员工身份。
- 身份采样在后台完成；待发送包落盘后重试保持原样，不用新的设备信息覆盖旧证据。

不能用 SSH 凭据上传审计数据。审计传输使用 HTTPS 和独立设备令牌，管理员读取采用独立认证。注册文件、队列、完整证据与管理员凭据不得进入代码仓库。

## 管理者视角设计基线

管理端按风险事件而非工具日志组织：风险总览、终端与 Agent、外联审计、数据外发、策略、审计证据。

风险详情应关联主体、设备、Agent、任务、数据来源、请求、实际连接目标、组织策略及处置证据。区分读取、进入上下文、观测到发送；区分组织批准网关、未批准中转和归属未知节点。

本项目已确认的企业审计范围是完整任务证据，包括已采集的请求、响应、工具、记忆与外联原文，不默认脱敏。新任务筛选不裁掉该请求本身携带的历史上下文。通过传输安全、独立认证和读取日志保护证据；企业目录、细粒度角色和保留期限仍需正式接入时实现。
