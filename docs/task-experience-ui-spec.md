# 任务体验 UI 验收基线

## 工具记录：解释与原文对照

- 工具记录不再重复展示同一条命令的标题、描述和代码块。主线及工具详情复用对照组件，解释与证据同时显示，窄空间上下排列。
- 点击说明高亮对应证据并暂停跟随；原文可选择、展开与复制。完整记录保留调用结构。
- 使用本地确定性规则说明已识别参数；表格 A1 范围解释行列边界；简单命令按引号外分号拆分，sed 行范围和 rg 搜索参数提供说明。
- 未可靠解析的脚本、未知字段、大参数保留原文并标明边界；不执行采集脚本，不声称知道 Agent 意图。嵌套 JavaScript 暂不自动拆解。
- 结果截断、正文缺失和整体耗时明确说明，退出码不能推导出任务成功。

## 2026-09-24 思考与执行原型（任务详情最新基线）

用户确认 [task-reasoning-story](prototypes/task-reasoning-story-approved.html) 后，任务详情以下列规则替代旧版左右等宽步骤阅读器；总览和历史列表保持已确认布局。

- 顶部状态横幅与耗时、当前动作、模型轮次、Token 指标；所有数值来自任务证据。
- 左侧主要区域为“思考与执行”：用户目标、逐轮模型说明、实际采集的推理记录、可读工具动作及结果。右侧为交付目标、文件产出、关注事项、思考记录覆盖。
- 点击上下文、响应、推理、代码/命令/结果后，证据在主线下方展开，不替换右侧摘要。
- 阅读证据时暂停跟随与自动刷新，包括忽略已经发出的自动读取结果；手动恢复后继续读取这项任务的新证据。收起证据不自动恢复跟随。
- 模型原文、采集推理/摘要、AgentReins 动作摘要分开展示；时间顺序不能描述为已证明的因果链。没有证据不编造计划、验收条件或工具结果传回模型的关系。
- 读取文件不等于产出文件。产出区只列创建、修改、删除或重命名的文件证据。
- 本次原生测试截图为测试数据，不能替代真实任务端到端验收；尚未覆盖安装目录的正式发布包。

任务详情与历史页基准为用户确认的 [task-story-v2-approved.html](prototypes/task-story-v2-approved.html)。2026-09-24 用户确认任务总览改为“本机 Agent 总览”：顶部三块概况（运行中的 Agent、执行任务的 Agent、当前模型），下方双列 Agent 卡片。三屏导航名称固定为：任务总览、当前任务、历史任务。旧 Dashboard/Operations 及第一版原型不再作为验收参照。

## v2 固定布局

- 顶栏：AgentReins 品牌、三个导航入口、采集状态。跟随系统明暗模式；颜色与间距取自原型。
- 总览：标题与副标题、三块运行概况、双列 Agent 卡片。卡片显示应用名、运行/任务状态、当前或最近模型、任务目标与进展、耗时、模型交互和 Token，以及进入任务或展开采集状态的按钮。按运行中本机应用去重，不计安装但未运行的应用或子进程，不把 Web 会话充当本机应用。
- 应用已运行不代表任务执行中；证据不全时标记“任务状态待确认”。只显示请求/响应中观测到的模型，不按默认配置猜测；实例来源若只有环境标签，不杜撰实例数量。
- 任务详情：任务名称和 Agent/时间、状态横幅、四项指标（耗时、模型交互、Token、文件）、左执行过程与右步骤详情，底部外联摘要。
- 首个步骤为用户目标；中间为真实请求、响应、工具与文件动作；有结束证据才出现结果步骤。每个步骤默认说明发生了什么、涉及什么对象、结果及耗时，原始证据折叠。
- 历史：按 20 项加载任务摘要，点击进入同一详情组件；不得自动将旧任务加入实时首页。
- 示例里的模拟完成按钮、固定数字、天气上下文提示仅用于原型演示。正式产品必须使用采集数据，不能写死或杜撰验证成功。

## 页面与入口

1. 应用打开后直接进入任务总览。列表以用户任务为单位，不以工具或事件为单位。
2. 点击任务进入独立任务页；左侧按轮次和动作顺序展示，右侧呈现当前所选动作的内容与证据。
3. 历史任务使用同一任务页，只是时间固定并允许回放；不得另做一套不一致的阅读器。

## 用户首先看到什么

- 任务：用户提出的目标、当前阶段、已观测耗时、模型请求/响应、工具完成/调用、已确认 Token、待审风险。
- 模型轮次：Agent 上传了什么（按来源拆解），模型返回了什么；只显示实际采集到的推理记录，不声称能看到不可见思维链。
- 工具动作：先用一句人话解释“做了什么”，再显示具体命令/路径、结果和耗时。工具内部名称、参数和原始输出放在可展开证据中。
- 文件、MCP、记忆与网络：展示具体对象、归属和可核对证据。模型外联、Agent 外部资源、SSH 分开标注。
- 采集缺口：明确写“未采集”或“无法可靠关联”，不把空值当作未发生。

## 发布门槛

- 用真实任务数据检查总览和任务详情，保留截图，确认点击后能进入任务页。
- 至少核对一条包含模型请求、响应、命令执行和文件变更的任务。
- 先完成调试构建和针对性测试；只有上述视觉与数据检查通过，才重新打包并覆盖 `/Applications`。
- 不以编译成功、安装成功或旧页面加入口代替 UI 验收。

## 当前实现边界

三屏布局、任务步骤选择、请求来源拆解、响应内容、可读工具动作、命令/结果/耗时、历史分页及独立调试预览包已实现。已用原生 SwiftUI 渲染检查总览、详情、请求、响应和工具页面，并用本机 WorkBuddy 任务核对请求与响应关联。

当前历史查看是点击步骤阅读证据，不是按时间游标重建任意时刻的完整状态。AI 辅助解释的隐私控制、真实新任务从下发到结束的整链路交互验收尚未完成。测试夹具截图不是生产任务证据；不得将预览版描述为完成商业发布验收。
