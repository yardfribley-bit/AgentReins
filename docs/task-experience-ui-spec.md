# 任务体验 UI 验收基线

此文档对应已确认的三屏原型：任务总览、实时执行链、历史回放。旧 Dashboard/Operations 的布局不作为新页面的验收参照。

## 页面与入口

1. 应用打开后直接进入任务总览。列表以用户任务为单位，不以工具或事件为单位。
2. 点击任务进入独立任务页；左侧按轮次和动作顺序展示，右侧呈现当前所选动作的内容与证据。
3. 历史任务使用同一任务页，只是时间固定并允许回放；不得另做一套不一致的阅读器。

## 用户首先看到什么

- 任务：用户提出的目标、当前阶段、已观测耗时、模型请求/响应、工具完成/调用、已确认 Token、待审风险。
- 模型轮次：Agent 上传了什么（按来源拆解），模型返回了什么；只显示实际采集到的推理记录，不声称能看到不可见思维链。
- 工具动作：先用一句人话解释“做了什么”，再显示具体命令/路径、结果和耗时。工具内部名称、参数和原始输出放在可展开证据中。
- 文件、MCP、记忆与网络：展示具体对象、归属和可核对证据。模型外联、Agent 外部资源、SSH 分开标注。
- 采集缺口：明确写“未采集”或“无法可靠关联”，不把空值当作未发生。

## 发布门槛

- 用真实任务数据检查总览和任务详情，保留截图，确认点击后能进入任务页。
- 至少核对一条包含模型请求、响应、命令执行和文件变更的任务。
- 先完成调试构建和针对性测试；只有上述视觉与数据检查通过，才重新打包并覆盖 `/Applications`。
- 不以编译成功、安装成功或旧页面加入口代替 UI 验收。

## 当前实现边界

任务总览与任务详情主路径、人类可读工具动作、历史任务索引已开始实现。历史回放的逐事件定位、AI 辅助解释的隐私控制及真实界面视觉验收尚未完成；这些不应被描述为已交付。
