# 实时采集与恢复的增量约束

本轮修复针对空闲重扫、旧任务重复计算和恢复检查点的周期性 CPU 峰值。只处理当前已观察及恢复的活跃工作集，不导入历史会话。

## 数据路径

1. 采集器把原始证据和来源游标提交到已有证据数据库。WorkBuddy Hook 仅在事务成功后确认收件文件；启动前的 Hook 保存原始字节后确认，不进入本次实时任务。
2. EventStore 通过 `liveEvidence` 发送本批新增或更新事件。健康状态刷新不重放最近 500 条事件。
3. 实时缓冲区保留事件身份与原文；只有超出工作集预算才安排转存。没有压力时不排序全部记录。未归属数量通过插入/替换增量维护。
4. 展示投影缓存未变化的会话；Codex 会话内进一步缓存任务轮次；新增上下文只使所属轮次失效，不使整个会话的旧轮次失效。缺失轮次的工具结果沿原生调用 ID 归组。WorkBuddy 保留代理流与原生会话的联合匹配，避免把网络会话当成人类任务。
5. 实时恢复写入 `realtime-active-v1.json.sqlite3`。`live_events` 按事件 ID 保存不可丢失的正文和修订，按 `(session,turn,ts)` 建索引。仅变化事件序列化和压缩，未变化事件不读取正文、不逐个检查旧正文文件、不重写 JSON 索引。恢复元数据与事件在同一个 SQLite 事务内提交，使用 WAL 和 FULL 同步。
6. 旧 JSON/LZFSE 恢复文件保留，首次数据库保存完成后从数据库恢复。数据库校验失败必须显式报错并保留原库，不静默回退到过时的 JSON。此迁移不查询全量证据历史。
7. 证据记录使用不可变引用，排序与分组只移动引用，不复制整份正文。实时模式保留采集器，但不运行未使用的旧安全看板派生计算。
8. 保存成功和转存成功不触发无内容变化的界面刷新。交付评估和网络地址列表随任务/产物变化更新；界面传输最多每秒合并一次，采集和证据入库不被这个频率限制。列表只传任务身份、原话、状态和搜索摘要，选中任务才携带完整执行详情。浏览器按任务修订读取独立详情文件，原生界面通过本地桥接选择任务；最多缓存五个已展开任务。详情导出以任务修订为依据，未变化任务不重复序列化其上下文。

## 不得退化的正确性

- 不把 Agent 停止等同于目标完成；保留停止原因、失败步骤和交付验证依据。
- 不以显示容量或缓存预算删除原始需求、工具返回或终止证据。
- 保存失败回滚事件与元数据，不能覆盖上一份可恢复状态。
- 异步上下文解析版本必须参加缓存失效判断，同 ID 正文修正不能复用旧解析结果。
- 修改事件归属时必须更新旧、新任务分组；不能只追加展示节点。
- 子 Agent 的委派身份不能伪装成人类原始需求。

专项测试证明：旧正文不可读取时未变化任务仍可复用；同会话新增轮次不重读旧轮次；数据库仅写新修订；事务失败保留原事件及已读/覆盖状态；旧格式无损迁移；数据库正文损坏明确失败；旧 Hook 入库后确认且不进入实时任务。

### 采集列表增量传输

每个缓存的采集记录带稳定 revision。首次加载发送完整列表，后续只发送发生变化的记录和完整 ID 顺序。浏览器保留原始正文，根据顺序移除离开窗口的缓存；同 ID 修复通过新 revision 更新，缓存缺失会请求完整重发。仅成功送达后确认修订版本，页面重载和重新请求会重置确认状态。独立预览文件保留完整内容。Swift 传输测试及真实 live.js 接收函数测试覆盖正文保留、顺序、删除、同 ID 修复和缓存恢复。


### 安装前数据边界（2026-10-12）

AgentReins 首次启用基于现有 JSONL 文件大小建立实时采集边界，不回放安装前正文；历史由 SessionLens 管理。此次审查确认实时 EventStore 不加载历史和不启动历史回填，现有 Codex 首启跳过正文。修正 WorkBuddy 的 512 KiB 上下文回读：缺失解析状态时也从已记录边界解析，不能用安装前需求补齐实时任务。

WorkBuddy 使用独立 `workbuddy-live` 游标命名空间保存首次启用时间、文件身份、偏移和实时解析状态。重启只恢复同一文件的实时游标，跳过此前历史游标；停机期间新增内容继续采集。预启用 Hook 仅从客户端临时待处理队列移除，不进入证据库；源会话文件和既有证据不删除。安装后新建流从头采集，取消旧 512 KiB 初始尾部限制以避免漏采。

Codex 在首次基线建立后立即保存游标。每个非空源仅保留最多 64 字节位置锚点用于重启验证，不解码这段历史正文。身份读取沿用有界会话元数据读取，不重放历史消息。

### 展示正文读取与近期索引优化

采集列表先比较工作缓冲 Record.revision，再读取缺失或修复的正文，缓存行复用同一修订。旧实现即使行展示缓存命中，仍先对整个列表 read()，导致冷存储的文件读取、哈希、解压和 JSON 解码重复发生。失败时保留此前完整列表，不发布部分构建结果。

缓冲以仅含 UUID 的近期索引维护最新 200 条与最多 100 条网络记录；不持有过时热正文。新记录只更新有界索引，普通同时间/类型正文修复只替换记录。时间或类型变化时重新计算窗口，补齐离开窗口的项；冷却后通过 UUID 取当前 Record。所有原始记录继续留在缓冲/冷存储中。

16 项缓冲/传输测试通过，包括新增一条仅增加一次正文读取、同 ID 修复后内容与修订变化、窗口与原全量排序选择一致、冷却后索引不持有旧热正文；实际 live.js 接收函数缓存回归通过。Release 包实际测量完成后另记结果。

本轮已实际构建并启动 Release，新 PID 13959；真实新增 6 个证据块与源文件哈希一致且连续覆盖。CPU 累计时间折算 68.5% → 65.0%，ps 均值 59.9% → 72.7%，负载变化、两种指标不一致，不能宣布整体降耗成功。新采样热点转向 live-encoding/JSON 字符串编码，具体报告见 AgentPair/docs/qa/agentreins-body-reuse-actual.md。
