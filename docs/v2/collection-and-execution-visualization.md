# 采集任务与执行任务：同一证据链的两条视角

参考：用户提供的 16.7 秒视频 2853_1791004554.mp4。视频画面中，移动的中心与连线在文档文字上活动，具体文本片段高亮并浮现，背景原文仍可定位。

参考的是“行动位置、被触及的具体内容、内容的流动”同时可见，不照搬霓虹、蜘蛛造型或随机线条。

同一任务固定展示两条轨道：执行轨道为用户需求→模型请求与响应→工具→进程及文件/网络行为→工具结果→后续请求；采集轨道展示每次动作对应的来源事件、正文片段、原生标识与关联结果。两条轨道引用同一证据 ID、时间和资源身份。

读取文件时高亮实际采集到的文件段落，并展示原始路径和读取证据。工具返回正文时，显示结果中具体的文字；正文进入模型请求时，定位该次上下文中的相应消息。没有采集到读取范围时，不把整份文件画成已读取。

生成文件时展示具体文件及已观测版本变化；网络连接展示进程、地址、端口和连接事件。仅有连接元数据时，不画成已取得 HTTPS 正文。工具调用未关联进程时显示断点。

采集轨道区分：原始事件已取得、正文已保存、任务归属已确认、关系未确认。动画由已提交事件驱动；历史播放明确标识为回放。落后或丢失以覆盖缺口显示，不因队列忙把事件偷偷删除。

接下来视觉迭代应围绕已确认的原型，用原工程真实任务投影替换占位节点；当前列表式原生视图仍只是中间验证，不是最终动态效果。
