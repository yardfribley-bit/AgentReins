# 性能回归约束

## 2026-09-24 高 CPU 定位

预览版 ui-v2-20260923.1935 的进程单次观测 CPU 为 95.6%。3 秒调用栈采样中，持久化队列的 387 个样本均位于 CodeChangeIndexer.build；热点是每个文件事件重新遍历整个会话。进程快照采集也是可见开销，不能把全部 CPU 归因于索引。

## 禁止重新引入的路径

- 每个文件关联用户目标/模型时遍历整个历史数组。使用按 session/turn 的索引，保留最早用户目标、最新上下文语义。
- 数据库忽略的重复事件仍触发派生索引重建。以事务实际插入的事件为准。
- 网络、Token、模型输出等不影响代码索引的批次触发代码索引重建。
- 在实时入库路径重建整个项目的 Change Set。该投影由历史查询按需构建。
- 当前任务详情因为同会话其他任务的变化而刷新。刷新依据必须限定到选中任务。
- 当前任务查询或外发审计载入整个会话。详情以 sessionId + turnId 查询，下一任务仅查询开始时间以限制 trace 归属；无任务归属的旧上下文不得默认挂到新任务。
- 只有回复/用量的孤立记录不能创建本次任务卡片，必须观测到本次运行后的任务请求起点。
- 实时代码索引只持久记录脏会话；标记与事件同事务入库，查询历史时重建后清除。重复事件不能重新置脏。
- 派生分析必须允许计算期间合并待处理快照，不得同步堵住 actor 后逐个执行旧请求。相同外部内容的扫描结果使用有容量限制的内存缓存，内容变化必须重新扫描。

## 每次修改必须检查

1. 运行 IndexPerformanceTests、AgentEventProtocolTests、TaskStoryRegressionTests。
2. 一万文件、100 个任务的测试必须保留完整归属，Debug 索引耗时低于宽松的 5 秒门槛；记录实际时间，不能仅提高门槛规避回归。
3. 重放同一批证据不得再次安排代码索引计算；无关事件不应触发代码索引。
4. 新预览进程必须核对路径与版本。记录真实 CPU 与采样，不把单次低值当成持续稳定。

## 尚需独立优化的边界

用户打开代码历史时仍会重建被标记会话的代码索引；历史摘要仍聚合事件表。这里没有宣称所有查询都已增量化。后续优化应保留跨轮次 checkpoint / verification 的补充关联，不能靠截断证据来降低耗时。

## 本轮验证

- 2026-09-24 完整 `swift test`：230 项，0 失败，3 项条件跳过。
- Debug 10,100 事件 / 10,000 文件索引：0.080 秒。
- 100,000 事件入库基准：47.60 秒，一秒召回率 1.0，最大快照 103.38 ms。
- 已打包预览版：`ui-v2-20260924.0410`。这些测试结果不替代长时间真实负载验收。
