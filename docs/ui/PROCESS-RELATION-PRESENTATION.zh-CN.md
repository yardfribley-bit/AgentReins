# 让办公用户看懂 WorkBuddy 的协作过程

本版为证据补齐后的界面设计依据，尚未更换现有界面。

## 用户首先需要得到的回答

- 我提出的需求，现在在哪里处理？
- WorkBuddy 动用了哪些能力？
- 每个环节拿到什么，做了什么，返回什么？
- 哪些环节是本机运行，哪些需要访问外部服务？
- 哪些是实际观察到的，哪些还不清楚？

## 主画面

采用稳定布局的组件关系图，以通俗用途命名，技术身份放在第二行或详情。默认不把全部 PID、端口、协议、启动参数铺在图上。

“工作窗口”（界面渲染进程）和“WorkBuddy 主程序”分开，不把主程序自动等同于界面。“应用后台服务”和“任务处理服务”（Agent 服务）保留已识别的职责范围。“同步相关服务”“辅助服务”在功能未知时保持该名称，不编造“记忆管理”“任务分发”等职责。

同一对组件的多个通道合成一条连接，详情标出通道数量及具体身份。新节点加入原有组件附近；结束观察的节点保留淡化状态；不因新事件持续改变节点位置。

## 连接的表达

| 主画面文字 | 可用证据 | 图形与动画 |
|---|---|---|
| 父子进程 | PID + 启动身份 + PPID | 细灰色结构线；详情说明采样时父进程，不伪造已捕获启动事件 |
| 已连接 | 双端 TCP / Unix Socket 对应 | 无方向实线；说明“已发现本机连接，具体传递内容尚未采到” |
| 发起工具调用 | Hook 的会话和调用编号、参数 | 有方向线，到工具活动节点；只有执行器身份确认后才连到具体进程 |
| 可能负责执行 | 调用方祖先 + 命令 + 启动身份 + 调用窗口 | 虚线，文字明确“执行进程待确认” |
| 返回结果 | 同会话、同调用编号的工具结果 | 返回方向动画，简要展示结果，不由 Socket 反推业务响应 |

动画由真实新记录触发。连接快照触发“发现连接”的短暂强调，不能画成持续传数据。请求和结果证据才能触发带方向的往返动画。历史证据只在用户回放时播放。

## 摘要和详情

每次活动用一句用户能理解的话，并保持依据可展开。例如采集到真实 ffmpeg 命令和工具结果后，显示“正在把视频放慢到 10 秒”“已生成文件 xxx_10s.mp4”；仅发现 ffmpeg 进程时，显示“发现视频处理工具，具体操作待对应”。

工具卡片默认展示“要做什么 / 交给工具的内容 / 工具返回什么”。输入和结果可折叠预览，全文按需查看。没有结果就显示“结果未采到”，不能用推测填空。

节点详情：这个组件是什么、技术身份、职责依据、近期活动。
连接详情：两端是谁、为什么画线、观测时间、输入和结果是否采到、原始依据。

当前任务的活动亮起；其他常驻组件以低对比显示。不能把所有后台活动归入当前任务。未匹配到任务的连接显示“本机连接，任务归属未确认”。

## 本次实测可展示的关系

六对连接可以先展示为静态真实关系，再叠加后续任务活动。安全 / 沙盒组件与任务处理服务确有连接；标注为“安全相关组件已连接”，不能显示“执行已受隔离”。组件并存与实际隔离是不同证据。

最终判断标准：非技术用户能讲出“我让它做什么、它找了谁帮忙、每一步拿回什么、结果从哪里来”；安全人员能在同一画面逐条追溯到证据。
