# AgentReins 实时生命周期工作台开发计划书

版本：1.0 · 2026-10-09 · 状态：待实施计划

## 1. 开发依据与目标

交互基准：[生命周期原型](../prototypes/lifecycle/index.html)，原型版本 `2044f90`；技术依据：[产品技术设计](PRODUCT-TECHNICAL-DESIGN.zh-CN.md)、[全生命周期细化](LIFECYCLE-DETAILED-DESIGN.zh-CN.md)。测试合同：[测试与验收文档](TEST-PLAN.zh-CN.md)。本次执行以测试方案v2及其逐项用例、连续验收手册为准；测试/开发不得自行用“不支持”豁免核心需求。

目标是将原型的三视图、任务入口、动态关系图和专用详情接到同一条真实任务证据链。用户能找到原始需求、判断当前进展、核对实际执行、打开产物。原型已有演示不计为生产能力已完成。

沿用独立分支 `codex/agentreins-realtime-visualization`。不替换原有采集技术，不接SessionLens、不做历史任务处理。原始证据持久化与活跃任务恢复继续属于本产品。

## 2. 当前基线与关键缺口

| 能力 | 当前基线 | 本期工作 |
| --- | --- | --- |
| 进程/文件/网络/IPC | 原有独立观察与证据库仍在 | 复用并核对真实采集；显式呈现归属和覆盖 |
| WorkBuddy消息/Hook/模型正文 | 已有采集与代理，问候场景曾验证 | 新任务输入及工具全链路现场核对 |
| Codex原生记录 | 已修部分消息格式、session/turn和完成事件 | 有状态增量解析、乱序/重复/跨窗口验证 |
| 实时任务与上下文 | 有有限缓存及投影、上下文解析 | 统一状态机、证据引用、起点保留 |
| 原型专用面板 | HTML演示数据与模拟推进 | 接入结构化真实数据，去掉模拟行为 |
| 命令全过程 | 有工具输入和返回，不能保证中间输出 | 能力探测、原生输出通道适配，明确来源限制 |
| 网络资源/IP归属 | 有连接及部分模型网络正文 | 资源层与连接层分离，增加可追溯归属元数据 |
| 产物/阅读/控制 | 尚无完整生产闭环 | 产物与验证模型、已读；控制按原生能力实现 |

审查发现的代码修复不等于运行版本生效；每次验收记录应用实际版本、采集器版本和源配置。既有测试通过记录不能继承为新增功能通过。

## 3. 交互原型到生产的映射

| 原型区域 | 生产数据/行为 | 完成条件 |
| --- | --- | --- |
| 左侧任务与查找 | 当前任务索引、原文/文件/工具/域名命中 | 命中定位到具体任务及对象，不仅筛任务标题 |
| 顶部原话与状态 | TaskRun原文引用、统一状态和currentStep | 不以标题代原文；所有视图状态一致 |
| 十二个环节入口 | 按能力和证据标记已发生/进行/未开始/不适用 | 不是固定顺序的打勾进度条 |
| 动态图与连线 | 因果关系、工具尝试、独立观察 | 每个节点/边可追溯；并行与重试不串联 |
| 执行时间线 | 原生事件时间、轮次和尝试 | 不把接收顺序等同发生顺序 |
| 专用详情 | 消息、终端、参数、diff、网络、预览组件 | 实际内容先呈现，技术元信息折叠 |
| 采集现场 | 来源健康、数量、延迟、覆盖、未关联记录 | 无任务也能看原有进程/文件/网络观察 |
| 四列结果看板 | 任务状态、结果、阅读状态 | 工具成功不直接把任务移入完成列 |
| 暂停画面 | 展示水位冻结，采集持续 | 恢复时补齐更新；不能遗漏起点 |
| 演示下一步 | 仅原型保留 | 生产删除按钮与演示数据 |
| 审批/取消 | 原生控制适配器与确认事件 | 不支持则明确不可用并提供定位，不放假按钮 |

## 4. 技术实施约束

事件事实、正文内容和展示投影分层。优先扩展既有GuardEvent及证据引用，在边界适配为TaskRun、Step/Attempt、ModelExchange、ExecutionSession、ResourceObservation、Artifact/Verification；不重写整套数据库或采集器。

标准事件包含稳定sourceRecordID、来源代次/序列、nativeTimestamp与observedAt、agent/session/turn/call/flow、内容引用和覆盖。任务键必须由原生身份或明确唯一关系构成。来源间重复消息以原生标识去重；相同文本重复输入不能吞掉。

状态归约在Swift层维护，JS只展示。任务状态、步骤状态、采集健康、产物验证与已读分别保存。明确终态不能被旧的晚到开始事件倒退；新轮次、重开和重试使用明确新版本或尝试。

UI数据流采用有版本的快照/增量；详情按对象和正文引用读取。内容超过预览限额显示覆盖边界并可继续读取，避免把整个上下文反复传入WebView。WebView桥接增加查询或控制入口时只允许结构化白名单动作，不接受任意JS、Shell或路径执行。

首次启动建立EOF基线；正常重启恢复已采活跃任务最小状态及游标。恢复不启动历史浏览/全库分析。启动扫描和游标建立的竞态必须测试；来源轮换/截断产生新代次，不能默默跳过缺口。内存淘汰优先清理展示缓存，原话与活跃调用由持久引用保留。

## 5. 分阶段工作包

### M0：冻结基线与采集能力核实

- 固定原型和生产资源路径，标注版本；建立可重复本机启动/停止流程。
- 核实WorkBuddy/Codex消息、工具、模型正文、中间输出、进程、文件、网络的实际能力矩阵。
- 读取既有历史技术资料和相关实现，记录复用点；测试自有命令/本地服务，不上传敏感内容。
- 为每个缺口区分源未提供、采集故障、解析遗漏、关联失败和展示遗漏。

交付：能力矩阵、运行基线、问题清单、最小真实任务证据。门槛：两端新输入能够定位到原始记录；缺口有明确归因。对应测试 CAP、ID。

### M1：任务身份、增量采集与连续性

- 保留每个流的session/turn/tool映射和半行缓冲；修复跨窗口、轮换、重复、乱序。
- 建立TaskRun及原文引用，支持原生新轮次、补充消息和会话活动；关系未知不强并。
- 活跃任务检查点、重启恢复和缓存起点保护；原始证据/检查点提交一致。

交付：稳定任务索引、关联依据与覆盖。门槛：两端真实原话进入当前任务；并行不串；重启边界可解释。对应测试 ID、RES。

### M2：统一状态、调用尝试与上下文循环

- 统一任务和步骤状态归约，明确等待确认、失败、取消、结束和状态未知。
- 将模型指令、执行开始、输出和返回分开；后台启动与最终完成分开。
- 原生请求响应配对、上下文版本变化、工具结果回流、用量去重。
- 无新进展提示用最后有效事件时间，不凭超时自动认定失败。

交付：Swift结构化任务快照和状态转移规则。门槛：并行、失败重试、晚到完成、断流和采集断开不误判。对应测试 ST、CTX。

### M3：执行与资源适配

- 命令：接入实际可用的输出增量、运行session、结束与业务状态；来源不支持时明确边界。
- Skill/MCP：说明加载、真实调用、远端提交/处理中/返回分别表达。
- 文件：本轮变化、实际内容、版本/diff、读取/写入证据。
- 网络：工具URL/浏览器/代理资源与系统连接分层关联；实际资源正文按已采能力展示。
- IP归属：可追溯离线库/缓存优先，异步补全、更新时间与失败状态；不查询示例IP，不主动探测目标补造资源。
- 进程：保留PID出生身份、资源、短命观察、独立记录和归属置信度。

交付：ExecutionSession与资源面板数据契约。门槛：每个显示字段有来源；真实命令和资源场景逐项核对。对应测试 EX、RS。

### M4：原型布局接入真实工作台

- 迁移浅色分栏、任务列表、三视图、图、时间线和各类详情；沿用原生WKWebView。
- 图节点位置稳定，按轮次/分支折叠；动画由新事件触发、一次结束，支持减少动态效果。
- 详情固定阅读版本，新内容提示；命令输出滚动锁与全文查找；上下文按角色、diff按文件版本排版。
- 任务搜索命中定位；图/时间线/面板双向联动；来源缺失与独立观察明确表达。

交付：可运行实时界面，不含模拟任务。门槛：用户能从原话找到当前步骤和内容，全部核心点击在生产WebKit可用。对应测试 UI。

### M5：交付物、阅读状态与控制边界

- 产物生成证据、存在性、打开/预览、失效状态和生成步骤追溯。
- 本轮变更与仓库全量状态分开；验证对象、版本、范围可核对。
- 四列看板统一状态，已读区保留本次完成任务；已读不等于认可。
- 原生支持的授权/取消接入确认通道；未支持能力不作为本期已实现控制。

交付：真实产物闭环、明确的控制支持表。门槛：两端分别完成适用的真实交付流程；所有承诺支持的控制完成实际验收。对应测试 OUT、CTL。

### M6：现场验收与发布

固定候选版本，完成两端真实任务、故障注入、性能测量和用户查找路径；修复阻断缺陷后回归相关范围。打包签名校验，记录版本和回滚包，证明采集器仍在而非只启动页面。交付测试报告与覆盖矩阵，生产入口明确。

门槛：测试文档的发布标准全部满足。界面截图、构建成功、测试数量不能单独作为放行依据。

## 6. 依赖、优先级与排期方式

依赖主链：M0 → M1 → M2 → M3 → M4 → M5 → M6。页面组件可在数据契约稳定后提前实现，但不能以静态数据验收生产功能。每个工作包均按“来源 → 关联 → 状态 → 页面 → 真实核对”闭环提交。

优先级：P0为原文/身份、状态正确、采集缺口、实际输入输出与交付定位；P1为资源补全、可读详情、完整查找、恢复与阅读体验；P2为动画细节和非核心视觉优化。P0缺陷优先于任何视觉加项。

工期采用阶段门槛排期，M0完成后依据中间输出、浏览器资源和原生控制的真实接入难度给出逐包工作量与日期。本文件不把未调查能力写成确定天数。每次更新记录“完成证据、剩余缺口、下一门槛”，由开发持续推进，无须用户逐次催促。

## 7. 风险与处理

| 风险 | 处理与退化 | 不允许的替代 |
| --- | --- | --- |
| 原生源不提供执行中输出 | 标明仅最终输出；评估已有执行session通道 | 最终输出逐行播放冒充实时 |
| TLS/远端内部不可见 | 分层覆盖与来源适配 | 仅凭IP猜URL或云端操作 |
| 活跃任务基线丢起点 | 游标/活跃状态恢复，中途接入明确缺口 | 扫全库回填再称实时 |
| 并行共享服务无法归属 | 留独立观察，等原生关联 | 时间近就归最新任务 |
| 巨量输出拖慢前台 | 正文引用、增量、背压与可见缺口 | 静默丢记录或无限内存 |
| 原生格式变化 | 兼容适配回归、未知格式健康告警 | 空结果当正常 |
| 原型控制无真实通道 | 显示支持范围与原生定位 | 点击按钮就变更成成功 |

## 8. 每阶段交付与变更管理

交付包包含代码提交、适用来源/版本、数据契约、关联证据、测试结果、界面截图、未覆盖项。新增字段或行为同步更新测试；不得悄悄删掉原型核心功能来达成通过。

采集器启停、权限/代理配置改动记录前后差异；保留上一可运行包。正式部署前检查有无活跃任务，避免重启破坏验收；发生不可避免缺口须明确记录。

交付汇报回答：哪些真实数据已采到；任务状态依据是什么；用户如何找到；哪部分尚不能证明。最终验收由真实链路和可交付物决定。
