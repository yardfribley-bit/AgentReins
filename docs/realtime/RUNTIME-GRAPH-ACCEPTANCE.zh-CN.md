# 架构流程 / 蜘蛛关系：实现和验收约定

以 docs/prototypes/agent-architecture/index.html 的用户认可版本为准。2026-10-09；独立实时 AgentReins，不接入 SessionLens。

## 界面约定

默认进入任务过程。左侧任务列表，顶部用户原话、当前步骤和任务状态；中央为动态图，右侧为点击对象的原始内容，底部为全部工具调用时间线。结果看板和采集现场为独立入口。

架构图固定16个模块：用户输入、感知、模型、上下文与记忆、规划、直接回答判断、输出、行动、目标判断、MCP/Skill、API、命令、数据库、文件、外部服务、观测。规划在左，记忆在右，行动与资源在下，保留返回模型的回路。安全、权限、人工确认模块和其连线已经删除。

架构流程保留确认原型的16个固定模块。蜘蛛关系恢复以真实模型/Agent为中心的放射关系：具体工具调用、工具返回、上下文、文件和网络资源按实际记录出现；默认展开最近6次调用及当前选中的调用，其余调用保留在可点击集合、完整下拉框和时间线。两种视图读取同一任务的原始证据，切换不改变所选任务与正在阅读的详情。缺少记录的模块灰显；没有配对证据的路径为虚线。只有新确认记录触发一次数据流动画，相同快照刷新不播放。

## 状态与依据

| 状态 | 触发依据 | 展示与结果 |
| --- | --- | --- |
| 进行中 | 实际输入、请求、工具开始或运行中的原生执行身份；尚无终态 | 显示真实当前步骤和已采输出，不虚构百分比 |
| 后台仍在执行 | Agent停止后仍有明确运行执行身份或原生后台任务清单 | Agent轮次结束与执行器分别展示 |
| 已停止·交付未确认 | 原生Stop、final_answer或task_complete；尚无明确交付/目标成功证据 | 显示最后答复、最后工具、此前失败及缺失返回；不列为完成 |
| 已完成未读 | 明确目标成功事实，或同轮present_files明确交付且文件路径实测存在 | 可打开产物；业务内容是否正确另外核对 |
| 失败/取消 | 原生任务级失败/取消事件 | 保留原生原因与记录；单个工具失败不升级为整个任务失败 |

真实来源的执行等待可在详情中保留，界面不增加权限/人工确认模块。没有结构化停止原因时，显示原文，不把文本关键词自动编造成原因。退出码0只表示该外层命令返回，不能证明安装、报告等用户目标完成。

活跃任务与未读终态任务可通过16 MiB有界检查点恢复；已读终态不再进入重启检查点。内存证据仍为32 MiB/6000条；超限明确报告，不悄悄宣称完整。原始证据来源不被改写。

## 采集与身份约定

- 原话只来自原生用户输入、Hook用户输入或真实请求的当前用户块；压缩摘要、环境注入和附件包装不充当原话。Codex附件无文字时保留附件类型和路径。
- WorkBuddy解析当前输入前先剔除cb_summary，网络与本地使用同一规则。当前原话位于长上下文尾部时，截断预览保留首尾，并注明完整正文覆盖情况。
- 模型请求按HTTPS flow/trace与响应配对。真实原话与唯一活跃原生轮次匹配时保持该轮次的整个生命周期，取消45秒截断；请求已归属后，晚到响应沿用同一flow。相同文本的并行轮次保持未关联。
- 工具按Agent/会话/轮次/call ID配对；同名Bash不合并。下一次请求只有携带同call ID并关联该实际返回证据，才确认结果回流。
- 进程父子关系、文件、网络连接和代理正文采集全部保留。系统进程/IP不自动等于某个工具的执行器或资源访问。
- 有源增量时展示输出时间线；只采到最终返回时明确表示缺少逐行过程。真实URL、方法、状态、IP、端口分别展示，不从IP编造URL或地理位置。

## 验收方式

自动测试覆盖采集解析、错乱需求、轮次/调用隔离、状态、增量输出、停止、明确交付和未读恢复。WebKit测试直接加载打包资源。浏览器用例覆盖节点/边点击、固定阅读、新内容提示、暂停画面、查找、看板、附件和多尺寸排版。

真实现场使用用户本次安装青简的已采原始切片、代理请求/响应和Hook结束记录。断言原话一致、20次原生调用与20次返回、13次模型请求、停止未完成原文可达、两种图共用详情，以及未被误列入已完成。该验收是已采现场数据校验，不冒充重新运行的任务。

运行入口：Tests/AgentReinsTests/WorkBuddyInstallFieldTests.swift；Tests/Manual/runtime-graph/install-field-ui.cjs。实际数据只保留在本机私有临时目录，不提交到仓库。

## 本次追加的验收项

- 默认为85%清晰阅读，正常节点标题保持可读；适应全图作为用户主动选择的概览。画布独立滚动，全图导航、定位当前、放大/缩小、100%与收起详情均可操作。1366×768、1680×900、1024×768分别验收；不以全图塞入屏幕作为默认阅读质量指标。
- Codex的additional_content页面注入和guardian内部自动评审不充当用户需求；内部记录仍在本次采集现场和原始证据中保留，不占用用户“未读任务”恢复预算。
- 一轮中的起始输入和后续补充各自保留时间、原话和证据ID。原生UserMessage与唯一同轮即时同文传输回声合并显示，重复发送和歧义不得合并。
- 重启后旧EventStore投影不得覆盖已经修复的活跃检查点。缓存压力先释放内部评审展示记录，保留Stop和它精确匹配的原生最终答复；不能因答复被挤出而把停止的安装任务重新显示成进行中。
- 浏览器18955入口使用原生应用同一份实时投影；断开时明确保留最后画面，不能继续标为实时。只读预览不具有文件打开等原生控制能力。


### 全图适配效果修正

清晰阅读保留原型的完整纵向布局和85%默认尺寸。适应全图使用同一组实际证据的紧凑概览：架构图保留16个模块及关系，压缩纵向空白、框内仅显示模块名称和真实状态；蜘蛛概览突出当前调用，其余调用聚合为可展开集合。关系未确认的路径继续虚线，不显示铺满画面的长线标。概览收起执行列表内容为画布留出空间，完整调用始终可从下拉框/聚合详情进入，切回清晰阅读恢复列表。

1366×768下架构概览从原先约17%的整幅缩略图改为约58%的紧凑图，名称和状态按固定可读字号呈现。三个桌面尺寸均验证全部16模块在窗口内，标题不被裁切，点击证据和阅读固定不受切换影响。对照截图来自真实Codex输入切片，属于视觉验证，不代替当前任务链路的现场验证。
