# 实时工作台卡顿定位与修复

2026-10-09，用户反馈界面卡顿。本次修改保留所有原有采集源及频率，没有靠停止进程／网络／文件观察降低负载。

## 实际定位

初始预览 PID 72157，占用约 98%–102% CPU。三秒采样 1209 个主线程样本中，832 个位于 RealtimeWorkspaceState.payload，799 个位于 RealtimeContextProjector.assemble。对每个上下文工具块重复扫描全部证据，造成主线程热点。

随后逐轮采样还发现采集列表重复生成、产物候选逐调用扫描全量证据、任务投影和 JSON 编码在主线程运行。只缓存上下文没有彻底解决问题；未将中间占用下降宣称为最终解决。

## 修改

- 模型响应按 Agent＋trace 建索引，工具结果按 Agent＋session＋call 建索引，保留原有时间及轮次歧义判断。
- 未变化任务／上下文复用缓存；重复 ingest 不发布新 revision。
- 采集列表按证据 ID 缓存（只保留展示的 200 项）；同一 ID 内容更新立即失效，进程快照未变时复用展示结果。
- 产物提取先筛选文件／工具结果与写入工具，以证据 ID 直接查找调用记录，消除每个工具遍历全部证据的循环。
- 原生 App 使用后台任务／上下文／产物关联投影，队列只处理一个在途快照，再追赶最新数据。持续输入时发布有序完整快照，防止一直等待“无新数据”才更新。
- JSON 编码移至后台；WebKit 推送合并，并以 250 ms 间隔追赶新快照，使用结构化参数继续保证转义安全。

## 验证

60 项相关测试通过：生命周期、产物、上下文、原生 WebKit，以及实际 REA 调研快照。新增检查：重复刷新不重建、同一证据 ID 修订可见、300 个上下文工具块与 5000 条无关记录隔离匹配、后台计算最终发布新工具输出。

测试日志 `/private/tmp/agentreins-lag-complete-tests.log`；签名打包日志 `/private/tmp/agentreins-lag-complete-package.log`。

最终预览 PID 76353 已启动。三秒采样共 1077 个主线程样本，其中 879 个在 App 事件循环栈，636 个在等待消息；此前主线程的 assemble／同步 JSON 编码热循环已移走。样本 `/private/tmp/agentreins-lag-delivery-sample.txt`。

## 尚有的性能限制

短时 CPU 测量仍出现约 20%–149% 的波动，后台大上下文投影、完整 JSON 快照编码及推送仍有负载。**这不是整体低 CPU 验收通过**。主线程采样改善也不能替代用户实际点击／滚动延迟测量。

当前推送仍是完整快照。后续应做按选中任务／详情的数据加载和增量 UI 更新，并建立真实负载下的点击／滚动延迟指标；不能为提速删掉采集证据。
