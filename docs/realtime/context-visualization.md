# 实时上下文循环

任务过程默认使用可点击的动态关系图，展示「我的需求 → 带给模型 → 模型返回 → Agent执行 → 结果进入上下文」。点击节点或连线在右侧查看详情；采集现场、完整进程观察树和结果看板继续保留。详见 dynamic-flow.md。

## 已实现

- 组成：系统/开发者说明、用户消息、助手消息与工具指令、工具返回、可用工具定义；兼容messages及Responses的input/instructions结构。
- 可读内容：文本直接显示；工具名称、用途、参数分别呈现。图片/文件仅显示已采引用，不下载或推定已读取全文。
- 请求切换：查看同会话本次运行已采请求，默认跟随本轮最新请求。
- 变化：按规范化完整块的SHA256及多重集合比较新增、保留、移出，重复消息计数独立；改变内容视为替换。仅同Agent/会话结构化请求可比较，不跨Agent、不将本地消息片段冒充模型请求。
- 工具回流：请求中的tool_call_id/call_id对应本次缓存的同Agent、同会话工具结果。多个轮次复用同编号时不强选；缺失关联保留未知。内容进入模型请求不等于模型已采纳。
- 模型响应：按Agent及原生trace/HTTPS flow配对，不凭最近时间猜测。展示实际文本、工具指令、provider返回的reasoning及已采tokens。
- WorkBuddy流式tool_calls按choice/index重组ID、名称和参数，单独保存为modelDecision；模型给出指令不虚构已经执行的工具事件。
- 原始来源、证据ID与关联边界按需展开；输入一律转义/使用textContent，不执行内容，不加载外部引用。

## 运行与性能

沿用现有采集器和实时EOF基线，不回填历史。新增解析在utility串行队列执行，按事件缓存；进程刷新不重新解析大正文。单请求解析上限8MiB；每块最多16,000字符，总预览256,000字符、最多500块。组成及变化指纹使用全部已解析块，预览截断明确提示。原始正文仍在原证据库。

Codex本地prompt通常仅是本地消息片段，明确标为「不代表完整模型请求」。没有完整请求正文时不补造系统说明、工具定义或对比结果。原生采集不能取得模型未返回的内部思考。

本次只读兼容验证使用已采到的WorkBuddy问候请求副本；不是生产应用的历史回填。真实工具多轮执行与回流仍需新任务现场验收。
