# 生命周期验收审查 · 2026-10-09

验收目标：用户能找到刚发出的原始任务、看懂当前步骤、点击获取真实输入输出并找到产物。构建成功和界面测试通过不能代替真实链路验收。

## 已确认

- 当前 Codex 会话本地原始记录包含用户原话和明确 turn_id。只读检查最近消息可见“对的”及此前的完整提问；不能把界面缺失归因于源头没有需求。
- 增量解析原先会尝试从片段首行 payload.id 获取会话 ID，而首行可能是消息记录。会话身份因此存在被消息 ID 覆盖的错误路径。修复为仅 session_meta 可提供该字段，片段使用 rollout 文件名中稳定会话 UUID。
- Codex task_complete 原先未映射任务结束。新增按原生 turn_id 的完成记录，表示 Agent 报告结束，不表示产物经过验证。
- 原文展示已经和短任务标题分离；缺失占位文本不再作为需求正文，也不再声称输入已记录。

## 尚未通过的真实验收

| 项目 | 当前结论 | 合格证据 |
| --- | --- | --- |
| 用户原文进入实时任务 | 源记录有原文；界面端到端待核对 | 同一原生会话及轮次，页面显示完整原话 |
| 模型往返 | WorkBuddy问候请求曾采到；本任务完整上下文未验证 | 请求响应原生标识及正文 |
| 工具执行状态 | 生命周期投影测试通过；现场链路未验收 | 同调用编号的开始、返回或失败 |
| 进程、文件、网络 | 保留独立采集；不能直接等同工具执行归属 | 原始系统证据与明确关联依据 |
| 任务完成 | 增加原生完成事件；需现场核对 | 原生结束事件，和产物验收区分 |
| 产物定位 | 尚未证明用户可直接找到并打开 | 实际产物路径、打开与内容验证 |
| 用户查找 | 尚未走通完整操作 | 找到任务→当前步骤→详情→产物 |

## 后续修复边界

不回填历史，不用时间相近硬接任务，不用独立系统活动证明某工具执行成功。重启会建立新的实时基线，重启前开始的任务可能缺少需求；不能在链路验收过程中不断重启并把缺失当成正常结果。
