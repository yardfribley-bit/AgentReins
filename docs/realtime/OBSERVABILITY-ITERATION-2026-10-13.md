# Agent 网络可观测性迭代验收

## 固定循环

每轮顺序执行：确认实际缺口 → 小范围开发 → 回归 → 优化构建 → 本机切换 → 真实 Agent 操作 → 对照任务、调用、进程、连接、正文、文件结果 → 记录下一轮阻塞。

不因自动测试通过宣称采集全覆盖。不批量扫描安装前历史，不代发 WorkBuddy 消息，不覆盖原始证据，不将命令参数作为 HTTP 正文。

## 第 1 轮：后台下载续接

发现：WorkBuddy 后台完成通知被过滤为上下文后，仍创建新轮次，导致实际工具结果与模型流分开。

修复：维护会话内原始调用到轮次的映射；通知中的 tool-use-id 唯一已知时恢复原任务及需求；迟到结果跟随原调用。调用标识跨轮次复用时取消确定归属。未知通知仍保留独立上下文，不按时间推断。

限制：针对增量解析。此前已保存的错误归属不会在本轮批量改写，需后续凭原生标识作可追溯重投影。

测试：WorkBuddyLivePipelineTests 5 项通过，包含新任务插入后旧后台调用返回场景。真实网络正文与 Git/curl 路径需要安装后单独实测。
