## 2. 测试对象、来源与前置条件

生产对象：指定提交构建的原生AgentReins实时应用及其WKWebView；WorkBuddy和Codex分别执行。`18953`页面只作设计对照，不计生产功能通过。

每次运行分配RUN_ID，例如 `WB-20261009-A01`，不得复用。记录机器、系统、Agent版本、应用路径/包哈希、采集器/Hook/代理版本、权限、开始/结束时间和源文件初始偏移。时间展示使用Asia/Shanghai，时延使用同机单调时钟或明确校准后的时间。

公共前置条件：

- **P-LIVE**：真实应用与来源已启动，查看运行路径确认版本；保留源水位；无其他同名测试；不在用例中途重启。
- **P-LAB**：按验收手册建立独立夹具目录和本地服务；记录ROOT、SERVER_URL、RUN_ID；数据不含真实凭证。
- **P-REPLAY**：在隔离XCTest目标调用现有解析/投影入口，例如CodexSight.parseSession与RealtimeWorkspaceProjector.tasks，输入用例指定的脱敏样本；禁止改写生产日志。需新增测试时将测试方法与fixture路径登记到运行报告。不存在对应驱动/方法则记阻塞，不能凭手工读代码标通过。
- **P-EVIDENCE**：测试版本能提供限定本次RUN_ID的标准事件与投影快照及内容引用；也可在测试构建直接从现有入口采样。若不可取得则定位为“可测试性阻塞”，不得用UI截图代替。当前尚未宣称已有统一导出命令。
- **P-CONTROL**：来源的原生授权/取消通道实际可用；不具备时控制用例阻塞并进入支持范围审查，不算通过。
- **P-PUBLIC**：已获授权、测试人员可核对请求的受控公网HTTPS资源，事先填写实际URL、预期正文哈希、访问记录和IP归属基准来源。未配置时公网用例阻塞，不用example.net或文档IP代替。

自动化实施登记表必须包含用例ID、测试方法/脚本路径、fixture路径、运行命令和报告路径。文档中的测试步骤并不表示这些生产能力或测试接口已经存在。

## 4. 独立证据与一致性断言

四层分别编号：**O**外部事实基准，**S**来源原始记录，**E**标准事件，**P**任务投影，**U**用户界面。O与S不得由P/U反向生成。

- O：测试人员保存的提交原话；fixture runner.jsonl（输出序号/通道/时间/结束）；server.jsonl（目标/状态/尝试/响应哈希）；测试目录文件原始字节、SHA256和独立验证结果。
- S：原生Agent消息/工具记录、Hook、代理及系统采样，记录准确流标识、字节区间/原生记录ID；只读保留本次时间窗，禁止扫描全库重放到生产。
- E：每个S记录的eventID、来源记录ID、session/turn/call/flow、内容引用、状态、时间及覆盖。
- P：任务身份、原话引用、currentStep、attempt、状态、产物/验证和投影版本。
- U：生产页面时间、对象标识/选中状态、内容及截图或录屏。

断言合同：

| 编号 | 可判定标准 |
| --- | --- |
| A-TEXT | 展示正文与提交用户文本一致，允许CRLF→LF；不裁掉空行/字符。不把环境包装当原话。附件单独计；仅明确脱敏字段可替换并说明 |
| A-ID | 所有确认归属记录的Agent/session/turn等于S；同call补turn只在唯一时成立；未知字段保持未知 |
| A-CALL | 同一尝试的开始/输出/返回call与attempt一致；重试有不同attempt；模型指令不算执行开始 |
| A-STREAM | 5行输出均有序号和来源时间；第1—4行在独立exit时间之前可见，首行UI延迟目标≤2秒；最终一次返回不通过 |
| A-STATE | 同投影版本三视图状态一致；仅允许状态表的证据触发；旧事件不能倒退终态 |
| A-CONTENT | 预览文本与内容引用对应，完整查看按字节哈希核对；明确截断位置；返回内容不凭模型叙述填充 |
| A-NET | URL/method/status与server原始日志一致；正文哈希相符；IP/端口来自连接证据，归属来自独立库且标更新时间 |
| A-OUT | 产物路径、字节哈希、预览内容与O一致；存在、验证、已读、认可分别维护 |
| A-TRACE | 每个确认节点/边可追到S/E；至少记录两个端点和关系依据；独立观察不可标确认因果 |

来源提供重试、摘要或脱敏时对账保留版本和对应规则，不能把未提供字段预期改成空并判通过。允许差异需事先进入运行说明，不在失败后临时放宽。

事件数量必须核对预先确定的关键集合：本任务用户输入、每个工具开始/返回、命令5个输出、服务两次请求、两份产物和结束事件。系统轮询样本数量不要求固定，独立对账时明确采样边界；不能宣称所有文件读/短连接零遗漏。

## 5. 状态转换判定表

| 输入证据 | 步骤状态 | 任务状态 | 禁止结果 |
| --- | --- | --- | --- |
| 用户输入，无开始 | 无执行步骤 | 待开始 | 因进程存在标进行中 |
| 原生开始/模型请求 | 对应步骤进行 | 进行中 | 默认百分比 |
| 模型下发工具指令 | 已请求/待执行 | 进行中 | 输出或执行器已产生 |
| 同call工具开始 | 执行中 | 进行中 | 仍标计划 |
| 明确审批请求 | 等待授权 | 等我确认 | 没请求仅沉默就标审批 |
| 某工具失败后继续 | 尝试1失败，尝试2独立 | 进行中 | 整任务失败/失败痕迹覆盖 |
| 仅工具成功 | 已返回 | 保持进行中 | 整任务完成 |
| 原生任务结束/明确最终回答 | 仍缺结束的步骤标返回未观测 | 已完成未读/已结束 | 自动补齐全部成功 |
| 原生任务失败 | 关联错误 | 失败 | 仅采集器断开即失败 |
| 原生取消确认 | 已取消 | 已取消 | 点按钮后未确认即取消 |
| 来源健康但60秒无新进展 | 原状态+最后进展时间 | 不自动改变 | 卡死/失败/待授权 |
| 来源断开 | 覆盖降级 | 保留最后有依据状态并提示待核对 | 无依据改任务失败 |

测试步骤中模型措辞允许变化，但原始输入、调用、来源身份、状态、输出、产物不得变化成无法对账的内容。模型不按提示执行时场景未建立，记阻塞/重做，不能把“无调用”标测试通过。

## 6. 用户查找与视觉验收

### 固定操作路径

在默认主页且至少4个当前任务时，测试者仅知道自己提交的原话：

1. 点击对应任务卡或搜索唯一原话标记，打开任务。
2. 不展开技术详情，指出原话、当前动作和等待对象。
3. 点击当前图节点，找到实际命令/参数及最新输出。
4. 从该步进入网络或文件详情；返回不丢选中任务。
5. 结束后从完成卡进入真实产物并打开预览。

验收：每一步无需原始日志、SQL或调用编号；任务到原话最多2次点击，当前步骤到对应详情1次，完成卡到产物预览最多2次。搜索后必须定位具体对象，只有标题过滤不能通过UI-05。记录点击数与实际失败点，不以主观“容易找到”代替。

### 视觉检查矩阵

固定390×844、736×1024、1024×900、1536×1050视口，100%/125%/150%文字缩放，分别检查默认任务、命令大输出、上下文长文、文件diff、网络详情、产物和看板。参考原型布局与保存截图，生产截图单独归档。

- 原话、状态、当前动作在任务页顶部内容区；标题不遮挡原文，原文可完整展开，不靠技术折叠区获取。
- 命令保留空格/换行；stdout/stderr有文字区别；用户上滚后新增输出不拉到底；长行可换行或在代码区局部横滚，整个页面无横滚。
- 模型按角色和顺序；文件diff有增删文本标识；网络首要区域含资源而非单IP；产物实际内容可预览。不允许统一大文本框代替专用面板。
- 长路径、500字符单词、中文段落、2000行输出不会遮挡按钮；每种状态有文字，不只颜色。
- 图节点、边标签、时间线不互相遮挡；窄屏重排或折叠，不能缩到不可读；正文不小于12px，次要标签不小于11px。与原型字体规范冲突时登记原型缺陷，一并修订，不照抄不可读尺寸。
- 所有核心按钮键盘可达、焦点可见；禁用有理由；内容新增不抢焦点。图边也需键盘等价入口。

每个组合填写通过/失败并附对应截图；“无溢出”只是其中一项。无截图或无实际检查的组合记未执行。

## 7. 发布门槛与例外规则

**必交核心（WorkBuddy、Codex分别验收）**：原话完整、可靠任务身份、不串任务、状态有依据、命令真实中间输出、实际输入/返回、文件与网络资源可核对、IP归属来源可解释、查找/点击可达、可交付结果、重启缺口不伪装完整。

EX-01不支持、源原话缺失、仅有IP无资源、搜索只筛标题、产物打不开，均不得以“适用来源缺失”转为通过。模型内部隐藏思考、任意第三方TLS解密、远端服务未披露内部不在全覆盖承诺内，但需如实呈现边界。

控制按逐来源支持表评审；不支持时必须通过CTL-03的诚实呈现，但CTL-01/02仍不算通过。若控制作为本期交付承诺，不支持即阻断。调整范围必须记录用户明确决定、受影响需求/用例和新的验收版本；测试或开发不能自行批准例外。

放行同时满足：

1. 必交需求全部有L4证据，双端E2E-01至06、08通过；E2E-07按批准控制范围执行。单元/原型测试不能替代。
2. 无S0/S1缺陷；全部必交P0通过且无未执行/阻塞。P1中涉及必交需求的失败同样阻断。
3. 每项R需求追踪结果完整，证据可定位，关键集合对账无未解释缺失/重复；未支持项单列且不伪装已实现。
4. 生产UI视觉矩阵、性能报告、签名/启动/采集存活和已验证回滚包齐全；目标未达标须记录，不静默放宽。
5. 独立复核者按完整验收手册可复现；负责人签署实际结论。没有复核者时标待复核，不能自称审核通过。

严重度：S0=正文被执行、越权读取/控制或凭证泄漏；S1=丢原话/串任务/假完成/伪实时/产物不可用/关键查找断裂；S2=非核心排版或降级说明缺陷；S3=不影响理解的视觉细节。优先级与严重度分别记录。

## 8. 执行结果与报告模板

结果：未执行、通过、失败、阻塞、不适用。阻塞记录缺少的具体环境/功能与责任项；仅设计明确不要求的场景可记不适用。每个变体、Agent、视口分别记结果，不合并成一个“通过”。

报告目录：`RUN_ID/manifest.json`、`submitted.txt`、`oracle/`、`source/`、`events/`、`projections/`、`ui/`、`artifacts/`、`results.csv`、`defects.md`。原始敏感材料仅本地受控保存，报告用脱敏引用；脱敏后保存哈希并注明不是原始哈希。
