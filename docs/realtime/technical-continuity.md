# 历史技术继承与实时生命周期可视化

## 产品边界

保留原有 AgentReins 的采集和关联技术，改造展示层。实时模式不回放旧任务、不执行历史分析；不以此为由停用进程、文件、网络、Hook 或模型正文采集。不接入 SessionLens。

## 生命周期验收合同

| 环节 | 来源 | 展示要求 |
|---|---|---|
| 应用运行与组件 | libproc 库存 | 主程序、服务、MCP、子进程、PID/出生身份/父 PID；暂时消失的节点保留并淡化 |
| 用户输入 | 原生 UserPromptSubmit / 本地消息 | 展示原文；仅有会话 ID 时保留会话级活动，不丢弃或假造轮次 |
| 模型往返 | 现有正文代理 / 原生记录 | 请求、响应、provider 返回的 reasoning、模型身份；缺失正文明确标记 |
| 工具/Skill/MCP | 原生 Hook / 调用记录 | 参数、调用 ID、返回、失败、等待；不能把所有未知工具叫 MCP |
| 执行与资源 | ProcessGuard / ProcessObservationCoordinator | 可执行路径、脱敏命令、内存/CPU、打开文件；句柄不等于全文读取 |
| 文件行为 | 原有文件观察 / 工具证据 | 路径、变更、已有正文与 diff；意图和系统观察分别保留 |
| 网络与 IPC | TCP/Unix采样、进程通信关联、模型正文 | 地址/端口/两端进程及正文覆盖；连接不等于已知传输内容 |
| 完成与结果 | 工具返回 / Agent final / 产物 | 返回结果与需求验收分开；缺失执行证据明确显示 |

关联原则沿用 V4：原始样本不被改写；无 Hook 也采集。调用方不是执行器；时间重合不足以关联；同会话调用 ID 只能在轮次唯一时补足轮次，多义时保持独立。

## 本次发现和修复

- 上一版新 UI 排除 `activity`，遗漏原生 Hook、进程资源、IPC 等真实证据的任务展示。
- 原生 Hook 使用 `hook_tool_finish`，新 UI 只识别 `hook_tool_end`；已兼容实际结束操作。
- 缺少 turn 的 Hook 曾被全丢弃；现在显示会话级活动。仅在同 Agent+session+call 原生键唯一时并入对应轮次。
- 复用原有进程登记器，保留退出观察的节点；在采集现场展示完整树和证据浏览，不要求先有任务。
- 复用原有证据展示器，显示进程资源、打开文件、网络/IPC、Hook、模型通信等类别。最近200条可筛选；明确标明本次缓存总数和预览数，避免把预览当成全部证据。
- 缺少任务标识的系统行为仍可查看，禁止硬塞给最新任务。Agent 归属未知的文件记录也保留为“归属未确认”。
- 现场健康检查发现旧 v2-preview 的孤立 mitmdump 占用18891，当前正文采集器因此退出。核验插件路径后接管；新增正常退出清理与代理父进程丢失自退出，防止崩溃/SIGTERM后继续占用。
- 现有日志 EOF 的无新增记录原先被计成 raw read failure；读取候选排除未增长文件，保留真正的读取失败与格式错误。

实时 EOF 基线、有限内存缓存和已批准视觉布局继续保留。此次是继承技术底座并修正展示适配，不重建采集架构。

## 尚待现场验收

本地单元/集成测试不能替代真实 WorkBuddy/Codex 任务。必须验证新输入、模型正文、实际工具、系统行为和结果能逐项出现；尤其核对当前运行版本、Hook 安装路径、代理存活及采集时间窗。18952 的原型页面不是原生实时应用的数据入口。

极短进程/短连接的轮询遗漏、无法提供的隐藏模型思考、未采文件读取正文属于既有技术边界，继续公开展示，不包装为全覆盖。
