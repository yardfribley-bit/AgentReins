# 实时生命周期开发与现场验收（2026-10-09）

分支：`codex/agentreins-realtime-visualization`。此记录更新并替代本文件之前的早期验证结论。

## 已完成的修复

1. 架构流程沿用已确认原型的16个模块和路径，移除用户不要的安全/权限/人工确认模块。蜘蛛关系使用独立的实际调用、返回、上下文、文件和网络分支，避免仅把架构模块换位置。完整工具调用仍可从下拉框和时间线查看。
2. 默认85%清晰阅读，画布、执行列表和详情独立滚动。支持放大、缩小、100%、适应全图、全图导航、定位当前和收起详情。原生窗口最低尺寸调整为900×600。
3. Codex按原生turn_id及来源类型解析用户输入；页面追加上下文、环境块及内部guardian评审不当成人的需求。同一轮保留起始输入和后续补充；传输/原生两条证据合并展示时保留双方ID。用户重复发送和不确定的回声不强行去重。
4. WorkBuddy压缩摘要不能充当原话。HTTPS请求用本轮唯一真实用户输入关联原生轮次，模型返回跟随同一flow身份；不因任务超过45秒而失去后续请求。代理时间戳支持小数秒。
5. Stop只证明执行结束，不能证明安装完成。实际安装的外层shell退出码0也不能掩盖sudo内部报错。保留停止原文、最后工具、错误返回和交付验证各自的来源。
6. 启动时旧数据库回放不覆盖修复后的恢复记录。内存压力保护真实原话、调用边界和与Stop精确配对的最后答复，优先处理内部评审展示记录。内部评审不占用用户未读任务重启预算，原始采集证据仍保留。检查点16 MiB、展示内存32 MiB/6000条限制仍明确可见。
7. 复用进程、文件、网络、Hook与HTTPS采集。IP连接和带方法/URL的实际资源分开表示；没有URL不能编造访问资源。通过只读本机预览服务把原生实时投影送到18955，gzip压缩并对未变化数据使用ETag。

## 实际现场证据

- Codex直接核对本轮原生JSONL里的“继续完成”“codex 的用户输入 一直采集失败”“修复 这个问题”：3条真人输入、6条原始传输/原生证据、2个原生轮次。页面注入不计为需求；补充输入可以在图节点详情中找到。后续屏幕反馈也已进入实时原话字段。
- WorkBuddy青简安装任务：原始需求为`https://github.com/qingjian-team/qingjian 帮我安装 这个项目，我本地已经下载了`。70条本轮原生记录、26条代理记录构成13次模型请求、20次原生调用及20次返回；真实最终答复说明安装无法由Agent全自动完成，包含`a password is required`。界面显示“已停止 · 交付未确认”，没有伪报完成。
- 现场曾发现缓存截断后安装最终回复不见、任务重新变为进行中；已恢复本次安装已采源记录并修复保留策略、重启覆盖问题。恢复前后均有检查点备份，其他新消息保留。
- 所有现场原始切片、完整代理正文、恢复文件及截图放在本机私有目录，不加入Git。
